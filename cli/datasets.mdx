The `veri datasets` group covers every dataset operation: upload local JSONL, connect a HuggingFace dataset, validate structure, inspect registered datasets, and manage append-only [dataset streams](/training/dataset-streams).

## Commands

| Command | Purpose |
| --- | --- |
| `upload <path>` | Upload a JSONL file. Auto-runs structural validation. |
| `connect-hf <repo>` | Connect a HuggingFace dataset. |
| `check <path>` | Standalone structural validator. |
| `preview <path> [--n N]` | Print the first N rows of a local JSONL. |
| `list` | List registered datasets. |
| `get <id>` | Show one dataset (streams: head, unsnapshotted rows, snapshot timeline). |
| `delete <id>` | Delete a dataset. |
| `create <name> --format F` | Create an empty append-only stream with a locked row format. |
| `append <name> <file\|->` | Append JSONL rows from a file or stdin (`--supersedes <row>` to correct a row). |
| `tombstone <name> <row>` | Remove a row from snapshots cut from now on (`--reason` required). |
| `snapshot <name> [--note]` | Cut an immutable snapshot at the current head. |
| `diff <name> <a> [<b>]` | Rows added, superseded, and tombstoned between two snapshots (default `b` is the live head). |
| `import-traces <name>` | Import a window of a deployment's request traces as rows. See [Import traces](#import-traces). |

## Upload a local JSONL

```bash
veri datasets upload ./datasets/train.jsonl --name my-train
```

`upload` runs structural validation before the network call. If validation fails, nothing is uploaded:

```bash
$ veri datasets upload bad.jsonl
Validation failed: 1 issue(s), 0 rows.
  • line 1: invalid JSON (Expecting value)

Use --skip-validation to upload anyway.
```

The validator checks:

- Each non-blank line parses as JSON.
- Every row is a JSON object (not a list or scalar).
- Row count is `> 0`.
- No duplicate `id` field values (when an `id` column exists).

To skip the local check (the server still rejects lines that are not valid JSON):

```bash
veri datasets upload dupes.jsonl --skip-validation
```

<Note>
  `--deep-check` is a reserved flag for tokenizer-dependent checks (length distribution). It is not yet implemented and emits a warning if passed today.
</Note>

`--name` defaults to the filename stem. Use `--quiet` for ID-only output that pipes cleanly:

```bash
DS_ID=$(veri datasets upload data.jsonl --quiet)
echo $DS_ID    # 0a1500ea6128
```

## Connect a HuggingFace dataset

No download required; Veri references the HF repo directly.

```bash
veri datasets connect-hf openai/gsm8k --config main --split train --name gsm8k-train
```

GSM8K requires a config name (`main` or `socratic`) — datasets with a single config can omit `--config`. Rename columns at connect time with `--map old=new` (repeatable):

```bash
veri datasets connect-hf openai/gsm8k \
  --config main \
  --split train \
  --map question=prompt \
  --map answer=answer
```

| Flag | Purpose |
| --- | --- |
| `--split` | HF split (default `train`). |
| `--config` | HF dataset config / subset name. |
| `--map old=new` | Column rename. Repeatable. |
| `--name` | Display name. Default derived from repo. |

## Validate without uploading

```bash
veri datasets check ./datasets/train.jsonl
```

Same validator `upload` runs, but standalone. Exits `1` on issues:

```bash
$ veri datasets check ok.jsonl
OK — 1000 rows.

$ echo $?
0
```

Use `--format json` for machine-readable output:

```bash
veri datasets check ok.jsonl --format json
# {"ok": true, "row_count": 1000, "errors": []}
```

## Preview rows

```bash
veri datasets preview ./datasets/train.jsonl --n 3
```

Reads the first N JSON rows from a local file. Useful before upload; for registered datasets use `veri datasets get <id>` followed by the dashboard.

## List, get, delete

```bash
veri datasets list                              # default 20 rows
veri datasets list --limit 100 --format json
veri datasets get 0a1500ea6128
veri datasets delete 0a1500ea6128
```

`delete` is irreversible. The CLI exits `0` and prints the deleted ID; no confirmation prompt.

## Streams

Streams are append-only datasets with immutable snapshots; training pins `name@latest` or `name@snap-N`. The full flow (create, append, supersede, tombstone, snapshot, diff, pinning a training job) lives on [Dataset streams](/training/dataset-streams). The short version:

```bash
veri datasets create acme-feedback --format preference
veri datasets append acme-feedback ./new-pairs.jsonl
veri datasets snapshot acme-feedback --note "week 2"
veri run configs/train.toml --set dataset.id=acme-feedback@latest
veri datasets diff acme-feedback snap-1     # snap-1 vs the live head
```

Every stream command accepts the dataset's name or id. `snapshot --quiet` prints the pinned `<id>@snap-N` reference for scripting. Pass a second snapshot to `diff` (`snap-1 snap-2`) once you have cut one.

## Import traces

`import-traces` takes a time window of one deployment's stored traces and appends them as rows on a stream:

```bash
veri datasets import-traces acme-feedback \
  --deployment 7c41e2a9b0d3 \
  --from 2026-09-11T00:00:00Z --to 2026-09-18T00:00:00Z \
  --snapshot
```

| Flag | Purpose |
| --- | --- |
| `--deployment`, `-d` | The deployment to read. Required. |
| `--from`, `--to` | The window, ISO 8601. Both required, at most 31 days. |
| `--format`, `-f` | `chat` (request and reply) or `prompt` (request only). Default: the stream's format. |
| `--model-version` | Only traces answered by this model version. |
| `--limit` | Most rows to import. Default and cap: 10,000. |
| `--snapshot` | Cut a snapshot right after the append. |
| `--force` | Import even if the window overlaps an earlier import. |
| `--score-evaluator NAME[@N]` | Only traces with an `ok` score from this evaluator. Narrow it with `--passed`, `--failed`, `--min-score` or `--max-score`. |

<Warning>
  A window takes every captured trace on the deployment, whoever made the call. On a deployment that several people or apps share, it takes everyone's chats.
</Warning>

The CLI and `client.datasets.import_traces` only take a window. To import one conversation or one call, use the REST route with `thread_id` or `request_id`: see [Import one conversation](/training/dataset-streams#import-one-conversation). It is also what **Add to dataset** does on the dashboard's Traces page.

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | User error (validation failed, missing flag, bad URI). |
| `2` | API error (server returned 4xx/5xx). |
| `4` | Auth error (no credentials, expired key). |
