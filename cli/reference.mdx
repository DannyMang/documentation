Reference material for the `veri` CLI: every global flag, every environment variable, the exit-code contract, the small `gpu` / `cost` / `billing` groups, and `veri doctor` for diagnostics.

## Global flags

Every command accepts these:

| Flag | Effect |
| --- | --- |
| `--format <fmt>` / `-o` | Output format: `table`, `json`, `jsonl`, `csv`. Default `table`. |
| `--json` | Documented alias for `--format json`. |
| `--quiet` / `-q` | Suppress banners and progress text. List/create commands print just the ID. |
| `-h` / `--help` | Show command help. |
| `--install-completion` | Install shell completion (bash / zsh / fish). |
| `--show-completion` | Print the completion script to stdout. |

`--format` and `--quiet` work on the root, on groups, and on every leaf command — they are spliced into every command's parameter list by the `VeriTyper` base class.

## Override syntax (`--set`)

Available on every command that loads a TOML config (`jobs create`, `jobs estimate`, `deployments create`, `environments create`, `environments update`, `run`). `veri config set` takes the same `KEY=VALUE` syntax as its argument.

```bash
--set <dotted.key>=<value>           # canonical
--set-string <dotted.key>=<value>    # force string parsing
```

Values parse as Python literals (numbers, `true` / `false`, quoted strings, lists; anything else stays a string); repeated flags build lists; scalar-vs-table conflicts error. See [the run-verb reference](/cli/run#override-toml-fields-from-the-cli) for the full rules.

## Help-on-missing-args

`veri` and every group (`veri jobs`, `veri datasets`, etc.) print help when invoked without a subcommand. Commands with required arguments print usage when those arguments are missing. Commands with no required arguments (`veri whoami`, `veri doctor`, `veri logout`, `veri billing balance`) just run.

```bash
veri                       # help
veri jobs                  # group help
veri jobs get              # usage: missing ID
veri whoami                # runs
```

## Exit codes

Deterministic across every command. Designed for shell scripting.

| Code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | User error (validation failed, missing flag, bad config). |
| `2` | API error (server returned 4xx or 5xx that isn't auth). |
| `4` | Auth error (401 / 403, missing credentials). |
| `130` | SIGINT (Ctrl-C). |

```bash
veri jobs get job_doesnt_exist
echo $?                    # 2
```

## Environment variables

Highest priority overrides the config file.

| Variable | Effect |
| --- | --- |
| `VERI_API_KEY` | API key. Overrides the file. |
| `VERI_API_URL` | API base URL. Overrides the file. |
| `VERI_CONFIG_PATH` | Path to the user config file. Overrides XDG. |
| `XDG_CONFIG_HOME` | Standard XDG override. Config moves to `$XDG_CONFIG_HOME/veri/config.toml`. |
| `VERI_PROFILE` | Reserved for Phase-2 multi-profile. Ignored today. |

```bash
# Override the active API key for one command (CI / scripts):
VERI_API_KEY=vk_other_key veri jobs list

# Use a non-default config (e.g., in CI):
VERI_CONFIG_PATH=/tmp/ci-veri.toml veri login --token vk_ci_key
```

## Config file location

Default: `~/.config/veri/config.toml` on Linux (XDG-correct), `~/Library/Application Support/veri/config.toml` on macOS, `%APPDATA%/veri/` on Windows (via `platformdirs`). `veri whoami` prints the active path.

The CLI auto-migrates the legacy `~/.veri/credentials.json` on first run **only** when no `VERI_CONFIG_PATH` / `XDG_CONFIG_HOME` is set. The legacy file is renamed to `.json.bak`, not deleted.

```toml
# ~/.config/veri/config.toml
active_profile = "default"

[profiles.default]
api_key = "vk_..."
api_url = "https://api.veri.studio"
```

Edit programmatically with the `--set`-style syntax:

```bash
veri config show
veri config show --format json
veri config set profiles.default.api_key=vk_new_key
```

## `veri doctor` — diagnostics

```bash
veri doctor
```

Runs five checks and reports `pass` / `warn` / `fail` per row:

| Check | What it verifies |
| --- | --- |
| `python` | Python interpreter version ≥ 3.10. |
| `sdk` | `veri-sdk` is installed and importable. |
| `config` | Config file exists and parses. |
| `credentials` | An API key is set (file or env var). |
| `network` | The API URL responds to `/health` with HTTP `< 500`. |

`doctor` always exits `0` — it reports, doesn't gate. Read the table, act on warnings. Use `--format json` to consume from CI:

```bash
veri doctor --format json | jq -e '.[] | select(.status == "fail")' && exit 1
```

## `veri gpu` {#gpu}

| Command | Purpose |
| --- | --- |
| `list` | The GPU offering matrix: per (GPU, provider), which node shapes you can order for training and serving, plus per-GPU $/hr. |
| `list --provider/--region/--gpu-type` | LIVE availability by region for the given filter. |
| `describe <sku>` | Hardware specs (VRAM, vCPU, host RAM, node size) + $/hr for one SKU. |
| `compare` | Compare cost across providers for a given GPU config. |

```bash
veri gpu list
veri gpu list --provider digitalocean
veri gpu describe A100-80GB
veri gpu compare --gpu-type A100-80GB --gpu-count 1
```

Bare `veri gpu list` is served from `GET /v1/gpu/catalog`: the `training` and `serving` columns show the GPUs-per-node shapes you can order (`1,8` means 1x and 8x nodes; `-` means the provider doesn't offer that workload; `(soon)` means wired but not enabled yet). Prices are per GPU per hour and appear once the provider's rate is seeded.

## `veri regions` {#regions}

| Command | Purpose |
| --- | --- |
| `list` | Launch regions for training jobs. Marks the default region and whether each region is available or coming soon. |

```bash
veri regions list
```

Pass a region to a training job with `veri train --region <name>`, `veri jobs create --region <name>` (or `region` under `[resources]` in the config), or the `region` argument of the `@training_job` decorator. Omit it to use the default region.

## `veri billing` {#billing}

| Command | Purpose |
| --- | --- |
| `balance` | Current credit balance. |
| `burn-rate` | Current spend per hour across running jobs and deployments, and the hours your balance covers at that rate. |
| `transactions [--limit N]` | Recent billing entries. |

```bash
veri billing balance
veri billing burn-rate
veri billing transactions --limit 50 --format jsonl
```

## `veri cost` {#cost}

| Command | Purpose |
| --- | --- |
| `estimate --gpu-type T [--gpu-count N] [--hours H] [--provider P]` | Price a GPU lease before you start one. |
| `summary [--days N]` | Your spend over the last N days (default 30). |

```bash
veri cost estimate --gpu-type L4-24GB --gpu-count 1 --hours 2
veri cost summary --days 30
```

## `veri settings` {#settings}

Workspace-level settings. Today that is the [retention window](/deployments/model-versions#retention) for model versions and dataset snapshots.

| Command | Purpose |
| --- | --- |
| `retention` | Show the workspace default retention window (default 90 days). |
| `retention --days N` | Set it. `0` opts into zero-data-retention. |

```bash
veri settings retention
veri settings retention --days 30
```

Per-lineage overrides live under `veri models retention <name>`; protected versions (alias targets, the previous production version, pinned or tagged versions, versions a deployment serves) are never purged.

## `veri wandb` {#wandb}

Account-level [Weights & Biases integration](/training/wandb): store your key once and every training job logs to your W&B account.

| Command | Purpose |
| --- | --- |
| `set [--api-key K] [--project P]` | Store your W&B API key (prompted with hidden input if omitted). |
| `status` | Whether a key is configured + the default project. The key is never shown. |
| `remove` | Disconnect; future jobs stop logging to W&B. |

```bash
veri wandb set --project my-experiments
veri wandb status
```

## `veri secrets` {#secrets}

Workspace-scoped [secrets](/secrets) for agent sessions. Values are encrypted at rest and never printed back.

| Command | Purpose |
| --- | --- |
| `set NAME --from-env VAR` | Store a secret from a local environment variable (also `--stdin`, or `--value`). |
| `set NAME ... --scope-host HOST` | Only attach the value to requests the sandbox makes to `HOST`. |
| `list` | Names and metadata. |
| `delete NAME` | Remove it. |

```bash
veri secrets set OPENAI_API_KEY --from-env OPENAI_API_KEY --scope-host api.openai.com
veri secrets list
```

## `veri api-keys` {#api-keys}

Mint, list and revoke API keys. `--deployment` mints a [model access key](/secrets#model-access-keys) that can only call that deployment's inference routes.

| Command | Purpose |
| --- | --- |
| `create NAME` | Mint a workspace key. The plaintext is printed once. |
| `create NAME --deployment ID [--expires-in SECONDS]` | Mint a deployment-scoped model access key. |
| `list` | Active keys (prefixes only). |
| `revoke KEY_ID` | Revoke immediately. |

```bash
veri api-keys create agent-prod --deployment 5b0e7c2d9a14 --expires-in 86400
veri api-keys list
```

## Evals commands {#evals}

[Evaluations](/evals): evaluators, experiments, human review queues, and the promotion gate.

| Command | Purpose |
| --- | --- |
| `evaluators create NAME` | Create an evaluator from flags (`--method`, `--output-type`, `--prompt`, `--judge-deployment`, `--source-file`, `--runtime`, `--binding`) or `--file spec.json`. |
| `evaluators version NAME` | Add the next immutable version; method flags merge into the latest config. |
| `evaluators list` / `get NAME [--version N]` / `archive NAME` | Inspect and retire evaluators. |
| `experiments run` | Create an experiment (`--dataset`, `--target`, `--evaluator`), wait, print per-evaluator results, and exit `1` unless it completed and passed. `--local` runs local code evaluators; `--json` prints the result. |
| `experiments create` / `get` / `list` / `items` / `cancel` / `diff` | Manage experiments without waiting; compare a run with a baseline. |
| `annotation-queues create` / `list` / `add` | Set up human review queues and add traces, threads, experiment items, or the targets of matching scores. |
| `models gate NAME` | Show, configure (`--snapshot`, `--evaluator`, `--threshold NAME=RATE`, ...), or turn off (`--off`) a lineage's promotion gate. |
| `models evaluate NAME@vN [--wait]` | Create the experiment the gate needs for a version. |

```bash
veri experiments run --dataset golden --target acme-bot@v7 --evaluator helpful --local
```

## Shell completion

Typer ships completion for free:

```bash
# Install for your current shell (writes to your rc file):
veri --install-completion

# Print the script without installing:
veri --show-completion
```

Supported shells: `bash`, `zsh`, `fish`, `powershell`.

## Versioning

```bash
veri version
veri version --format json
```

Prints SDK version, Python version, and platform string. The `--version` and `-v` root flags are aliases — they emit the same output and exit. From CI:

```bash
test "$(veri version --format json | jq -r .sdk_version)" = "0.2.42" || exit 1
```

## Phase-2 deferrals

These are not available yet; the CLI rejects them as unknown commands:

| Feature | Gated on |
| --- | --- |
| `veri jobs resume` | Resumable training-runner checkpoints. |
| `veri jobs ssh` | SSH ingress into training containers. |
| `veri jobs metrics --export wandb` | SDK metrics method. |
| `veri deployments start` / `rollback` / `history` | Server-side versioned deploy history. Scale with `veri deployments update`. |
| `veri deployments load-lora` / `unload-lora` | Multi-LoRA inference backend. |
| Multi-profile (`veri profile use/new`) | Forward-compatible schema already in place. |
