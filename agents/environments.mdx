## Overview

An environment is everything a session needs except the conversation: which harness runs, which model it talks to, how big the sandbox is, what the network may reach, which secrets and MCP servers are available, which skills are installed, and which tools are allowed. Create one, then start as many sessions from it as you like.

Every edit is a new **immutable version**. A session pins the version it started with, so changing an environment never alters a running or paused session.

## Create one

```toml environment.toml
kind = "environment"
name = "coder"
description = "Claude Code on our fine-tuned Qwen"

harness = "claude-code"          # the only harness today
size = "standard"                # small | standard | large (sets the hourly rate)
egress = "restricted"            # restricted (default) | unrestricted
allowed_hosts = ["api.example.com"]
secrets = ["GITHUB_TOKEN"]       # names from `veri secrets`
skills = ["pdf-processing", "git-hygiene@2"]
idle_timeout_s = 900

[model]
deployment_id = "1a2b3c4d5e6f"   # a Veri deployment id, OR:
# base_url = "https://api.openai.com/v1"
# secret = "OPENAI_API_KEY"      # sent only to that host

[env]
LOG_LEVEL = "info"

[[mcp_servers]]
name = "tools"
url = "https://example.com/mcp"  # your MCP server
secret = "TOOLS_TOKEN"

[permissions]
default = "allow"                # allow | ask | deny
rules = [
  { tool = "Bash(rm *)", action = "ask" },   # stop and wait for you
  { tool = "WebFetch", action = "deny" },
]
```

```bash
veri run environment.toml          # or: veri environments create environment.toml
veri environments list
veri environments get <id> --toml  # round-trips the normalized spec
veri environments update <id> environment.toml   # appends a new version
```

```python
from veri_sdk import Client

client = Client()
env = client.environments.create(
    "coder",
    model={"deployment_id": "1a2b3c4d5e6f"},
    secrets=["GITHUB_TOKEN"],
    skills=["pdf-processing"],
    permissions={"default": "allow", "rules": [{"tool": "Bash(rm *)", "action": "deny"}]},
)
env["version"]["spec"]   # the normalized spec that sessions will run
```

## Fields

| Field | Meaning |
| --- | --- |
| `harness` | `claude-code`. OpenCode, Codex and custom images are planned and rejected with a clear message until then. |
| `model` | Exactly one of `deployment_id` (a Veri deployment in this workspace; each session gets a short-lived [model access key](/secrets#model-access-keys) automatically) or `base_url` plus an optional `secret` holding its API key. |
| `size` | Sandbox CPU and memory tier, which also sets the session's [hourly rate](/agents/sessions#pricing-and-limits): `small` (1/2 vCPU, 4 GiB memory, 8 GB disk), `standard` (1 vCPU, 6 GiB, 12 GB; the default), `large` (4 vCPU, 12 GiB, 20 GB). `xlarge` is planned and rejected with a clear message until then. |
| `egress` | `restricted` allows only the built-in hosts (Veri API, GitHub, npm, PyPI), your `allowed_hosts`, the model host and every MCP host, over HTTPS. `unrestricted` is open internet. |
| `env` | Plain environment variables. The eight names the runtime sets are rejected as `env` keys and in `secrets`: `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `VERI_API_KEY`, `VERI_API_URL`, `VERI_SESSION_ID`. Other names with those prefixes are fine. |
| `secrets` | [Secret](/secrets) names. A secret without `scope_host` becomes an environment variable; one with `scope_host` is attached only to requests for that host and never enters the sandbox. |
| `mcp_servers` | Streamable-HTTP MCP servers written into the harness's MCP config. The URL must be HTTPS and resolve to a public address when you create the environment. `secret` is sent as a bearer token. |
| `skills` | [Skills](/agents/skills) by name (latest) or `name@N`. The resolved versions are pinned in the spec. |
| `permissions` | `default` (`allow`, `ask` or `deny`) plus `rules`, tool patterns in the harness's own syntax (`Bash(rm *)`, `WebFetch`) evaluated top to bottom with the last match winning. See [Permissions](#permissions). |
| `idle_timeout_s` | Seconds without input before the session snapshots its workspace and pauses (60 to 21600). |

The API returns the **normalized** spec: defaults filled in, hostnames lowercased, duplicate entries removed, skills pinned, and every secret the spec references (including the model's and each MCP server's) listed in `secrets`. That is exactly what the sandbox is built from, and what `veri environments get --toml` prints.

## Permissions

- `default = "allow"` runs the harness in Claude Code's `bypassPermissions` mode: every tool call that no `deny` rule matches runs without a prompt. Sessions are unattended, so this is the mode to use when the sandbox and the egress allowlist are the boundary you rely on.
- `default = "deny"` runs it in `dontAsk` mode: only tools matched by an `allow` rule run; everything else is refused without a prompt and the agent is told so.
- `deny` rules bind in every mode, including `bypassPermissions`. `allow` rules only matter under `default = "deny"`.
- `ask` stops the session for a human decision. When the agent calls a tool whose last matching rule is `ask` (or any tool, under `default = "ask"`), the harness parks the turn before the call runs, the session becomes `awaiting_approval`, the transcript gets an `agent.approval_request` and the `session.approval_requested` [webhook](/webhooks) fires. Answer with `user.approval` (`veri sessions approve <session> <approval> allow|deny [--message]`, the session page, or `POST /v1/sessions/{id}/events`); on `allow` the call runs and the turn continues, on `deny` the agent reads your message as the reason and continues without it. If the approval check itself cannot complete, the call is refused, never run. See [Approvals](/agents/sessions#approvals). [Triggers](/agents/triggers) run with nobody to answer, so an environment that uses `ask` cannot be triggered.

Rules are a flat list and the **last match wins**: `[{tool = "Bash", action = "ask"}, {tool = "Bash(git *)", action = "allow"}, {tool = "Bash(rm *)", action = "deny"}]` asks for every shell command except `git ...` (allowed) and `rm ...` (denied). `Bash(prefix *)` matches commands starting with `prefix`; `Read(/etc/*)`, `Edit(*.md)` match the file path; `mcp__server__*` matches every tool of an MCP server; `*` matches everything.

What to expect while a session waits:

- Nothing bills: the sandbox is snapshotted and stopped the moment the turn parks, and restored when you decide (a few seconds, like a resume).
- A request expires after 30 minutes without an answer and counts as a `deny` (the transcript shows `user.approval` with `reason: "timeout"`); the turn resumes so the agent can finish without the call.
- `user.message` returns `409` until the pending approval is answered. One approval is open at a time; a second `ask` that fires meanwhile is denied, not queued.
- `ask` is best effort, like every rule that governs `Bash` and file tools: it is enforced by the harness's own permission system inside the sandbox. `deny` rules, the egress allowlist and secret scoping are the hard boundaries.

## Versions

```bash
veri environments get <id> --version 1
```

`POST /v1/environments/{id}/versions` with a full spec appends version `latest + 1`. Deleting an environment hides it and stops new sessions; existing sessions keep their pinned version.
