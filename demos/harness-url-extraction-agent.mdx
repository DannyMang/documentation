The end-to-end [harness-in-the-loop](/training/harness) flow, on the task **"given an arXiv paper, find its GitHub URL"** — a verifiable-reward agent task. Your harness is a plain OpenAI-SDK tool loop with nothing Veri-specific in it; the same shape works for any harness (LangChain, OpenAI Agents SDK, Claude Agent SDK).

<Note>
  Harness training is **experimental** — expect rough edges on the GPU path and please report them. This spends real GPU credit; check your balance with `veri billing balance` first.
</Note>

## Prerequisites

- Install the SDK: `pip install veri-sdk`
- Authenticate: `veri login` (or set `VERI_API_KEY`)
- Read the concept page once: [Harness-in-the-loop RL](/training/harness) (the env contract below is what makes the "unmodified harness" part work)

## 1. Dataset: one task per row

Each row needs a `prompt` (what the agent sees) plus any columns your reward function uses (here `answer`, the ground-truth URL):

```jsonl tasks.jsonl
{"prompt": "Find the GitHub repository URL for the arXiv paper 2305.10601 (vLLM). Answer with just the URL.", "answer": "https://github.com/vllm-project/vllm"}
{"prompt": "Find the GitHub repository URL for the arXiv paper 2210.11416 (TRL). Answer with just the URL.", "answer": "https://github.com/huggingface/trl"}
```

Upload it: `veri datasets upload tasks.jsonl --name agent-tasks` → note the dataset id.

## 2. Reward function: score the finished trajectory

A TRL-format reward. `completions` is the trajectory's **final assistant message**; extra dataset columns arrive as kwargs:

```python reward.py
def reward(prompts, completions, answer, **kwargs):
    rewards = []
    for completion, expected in zip(completions, answer):
        text = (completion or "").strip().rstrip(".")
        rewards.append(1.0 if expected in text else 0.0)
    return rewards
```

Upload it: `veri rewards upload reward.py --name url-match` → note the reward id.

## 3. The harness: your agent, unchanged

`agent.py` — a plain ReAct-style tool loop against `OPENAI_BASE_URL`. Nothing Veri-specific (the model replies `FETCH: <arxiv_id>` to read a page, `ANSWER: <url>` when done; no native tool-calling needed, so it works on any vLLM config):

```python agent.py
import json
import os
import re
import urllib.request

from openai import OpenAI

client = OpenAI()  # reads OPENAI_BASE_URL / OPENAI_API_KEY from the env
MODEL = os.environ.get("VERI_POLICY_MODEL", "Qwen/Qwen3-4B")
MAX_TURNS = int(os.environ.get("VERI_MAX_TURNS", "8"))

SYSTEM = (
    "You find GitHub repository URLs for arXiv papers. On each turn reply with "
    "EXACTLY ONE of:\n"
    "  FETCH: <arxiv_id>   to read the paper's abstract page (e.g. FETCH: 2305.10601)\n"
    "  ANSWER: <url>       when you know the GitHub URL\n"
    "No other text."
)

def fetch_arxiv(arxiv_id: str) -> str:
    url = f"https://arxiv.org/abs/{arxiv_id.strip()}"
    req = urllib.request.Request(url, headers={"User-Agent": "veri-demo-agent/1.0"})
    with urllib.request.urlopen(req, timeout=30) as resp:
        html = resp.read().decode("utf-8", errors="replace")
    text = re.sub(r"<[^>]+>", " ", html)
    return re.sub(r"\s+", " ", text)[:3000]

task = json.loads(os.environ["VERI_TASK_INPUT"])
messages = [{"role": "system", "content": SYSTEM}, {"role": "user", "content": task}]
for turn in range(MAX_TURNS):
    resp = client.chat.completions.create(model=MODEL, messages=messages, temperature=0.7, max_tokens=512)
    content = (resp.choices[0].message.content or "").strip()
    messages.append({"role": "assistant", "content": content})
    if content.upper().startswith("ANSWER:"):
        break
    match = re.match(r"(?i)^FETCH:\s*(\S+)", content)
    observation = fetch_arxiv(match.group(1)) if match else "Reply with FETCH: <arxiv_id> or ANSWER: <url>."
    messages.append({"role": "user", "content": f"OBSERVATION:\n{observation}"})
```

```text requirements.txt
openai>=1.0
anthropic>=0.40
```

The complete, runnable bundle (both SDK variants, tasks, reward, and a local smoke script that runs the loop against any endpoint) lives in the repo at `tests/documentation_tests/Documentation/Demos/Harness URL extraction agent/`.

## 4. Submit

```bash
veri run-harness ./harness \
  --entrypoint "python agent.py" \
  --base-model Qwen/Qwen3-4B \
  --dataset-id <dataset id> \
  --reward-id <reward id> \
  --gpu-type L4-24GB --gpu-count 1 \
  --rollouts-per-prompt 8 --max-steps 50 \
  --requirements ./harness/requirements.txt
```

One node colocates the policy server, rollouts, and the trainer — a 4B policy fits comfortably on a single L4.

## 5. Watch it learn

Open the job in the dashboard → **Trajectories** tab. Pick a policy step, pick a task, compare the N trials: full message history of every turn, tool calls, per-turn token counts, and the reward. Flip between step 0 and the latest step to see behavior change. Download any trajectory as raw JSONL — or programmatically:

```python
rows = client.training_jobs.trajectories(job_id, policy_step=10)
url = client.training_jobs.trajectory_download_url(job_id, rows[0]["id"])
```

## 6. Deploy the result

The trained checkpoint is on the job like any managed run — **Save as model**, then `veri deploy`, and point the same harness at the deployment endpoint.

## Claude Agent SDK variant

The same loop through the Anthropic messages API — the SDK reads `ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN`, both injected per rollout. Submit with `--harness-protocol anthropic`:

```python agent_anthropic.py
import anthropic

client = anthropic.Anthropic()  # ANTHROPIC_BASE_URL / ANTHROPIC_AUTH_TOKEN from the env
MODEL = os.environ.get("VERI_POLICY_MODEL", "Qwen/Qwen3-4B")

# ... same ReAct loop; completions come from:
resp = client.messages.create(model=MODEL, max_tokens=512, system=SYSTEM, messages=messages)
content = "".join(b.text for b in resp.content if b.type == "text").strip()
```

```bash
veri run-harness ./harness --entrypoint "python agent_anthropic.py" --harness-protocol anthropic ...
```

<Warning>
  For training-fidelity rollouts, the OpenAI route is the verified path today: token-id capture through the Anthropic route is unconfirmed, and spans without token ids are rejected from training (fail-safe, never silent drift). Running this variant is exactly how that gets verified — watch for `template_drift` errors in the job log (the S2 answer).
</Warning>

## Config-file form

`veri run` accepts the same job as TOML. Upload the harness directory first (any `veri run-script ...` upload or `client.code_artifacts.upload(dir)` returns an artifact id), then:

```toml configs/harness.toml
kind = "train"

[model]
base = "Qwen/Qwen3-4B"

[dataset]
id = "<dataset id>"

[reward]
id = "<reward id>"

[resources]
gpu_type = "L4-24GB"
gpu_count = 1

[method]
type = "grpo_harness"
rollouts_per_prompt = 8
max_steps = 50
harness_protocol = "openai"
max_turns = 40

[harness]
base_image = "veri/base"
code_artifact_id = "<artifact id>"
entrypoint = "python agent.py"
```
