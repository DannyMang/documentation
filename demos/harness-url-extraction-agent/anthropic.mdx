A [harness-in-the-loop](/training/harness) variant of the [URL-extraction demo](/demos/harness-url-extraction-agent) over the **Anthropic messages protocol**. A common production shape for this kind of task is an agent SDK with built-in tools (the Claude Agent SDK's Bash / Read / WebFetch); the closest equivalent that runs in Veri's Python rollout images today is the stock `anthropic` SDK driving **native tool_use blocks** — identical `/v1/messages` protocol path, no CLI needed. The client reads `ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN`, both injected per rollout.

## The harness

`agent_claude.py`:

```python agent_claude.py
client = anthropic.Anthropic()  # ANTHROPIC_BASE_URL / ANTHROPIC_AUTH_TOKEN injected per rollout
MODEL = os.environ.get("VERI_POLICY_MODEL", "Qwen/Qwen3-4B")

TOOLS = [{
    "name": "web_fetch",
    "description": "Fetch a web page and return its visible text (truncated).",
    "input_schema": {
        "type": "object",
        "properties": {"url": {"type": "string"}},
        "required": ["url"],
    },
}]

messages = [{"role": "user", "content": task}]
for turn in range(MAX_TURNS):
    resp = client.messages.create(model=MODEL, max_tokens=1024, system=SYSTEM, tools=TOOLS, messages=messages)
    messages.append({"role": "assistant", "content": resp.content})
    tool_results = [
        {"type": "tool_result", "tool_use_id": b.id, "content": web_fetch(b.input["url"])}
        for b in resp.content if b.type == "tool_use" and b.name == "web_fetch"
    ]
    if not tool_results:
        break  # final answer
    messages.append({"role": "user", "content": tool_results})
```

## Run it

Same dataset, reward, and submit flags as the [main demo](/demos/harness-url-extraction-agent) — different entrypoint and protocol:

```bash
veri run-harness ./harness \
  --entrypoint "python agent_claude.py" \
  --harness-protocol anthropic \
  --base-model Qwen/Qwen3-4B \
  --dataset-id <dataset id> --reward-id <reward id> \
  --gpu-type L4-24GB --gpu-count 1 \
  --requirements ./harness/requirements.txt
```

```bash
# local smoke:
python smoke_local.py --protocol claude --base-url <endpoint> --model <name> --api-key <key>
```

<Warning>
  **For training, the OpenAI route is the verified path today.** Token-id capture through the Anthropic route is unconfirmed: spans without token ids are rejected from training (fail-safe, never silent drift). Running this variant is exactly how that gets verified — watch for `template_drift` errors in the job log. Native tool_use additionally needs tool-calling flags on the vLLM side; if the model can't emit tool_use blocks it falls back to plain-text answers, which tells you the flags are missing.
</Warning>

<Note>
  The **Claude Agent SDK proper** wraps the `claude-code` CLI (Node.js), which the Python rollout images don't ship today — an image with the Agent SDK runtime is a follow-up. The variant above exercises the same protocol with the same harness shape. A plain-text Anthropic variant (`agent_anthropic.py`, no tool blocks) is also in the bundle if you want the protocol path without the tool-use requirement.
</Note>
