Veri runs training jobs on three GPU providers. You pick one at job submit time with the `provider` field. Each provider offers different GPU types at different price points: AWS is the default, Vast.ai is the NVIDIA marketplace spillover, and DigitalOcean offers single-GPU H100 droplets with per-second billing.

## Providers at a glance

| Provider | GPUs offered | Architecture | Billing | Status |
| --- | --- | --- | --- | --- |
| [`aws`](/training/providers/aws) (default) | L4, A10G, A100 80GB, H100 80GB | NVIDIA (Ampere/Hopper) | Per-second, on-demand or spot | Available |
| [`vast`](/training/providers/vast) | A100 80GB, H100 80GB | NVIDIA (marketplace) | Per-second, marketplace pricing | Available |
| [`digitalocean`](/training/providers/digitalocean) | H100 80GB | NVIDIA (Hopper) | Per-second, on-demand | Available |

<Note>
  All providers except AWS are gated behind feature flags that may be off in your environment. If a provider is disabled, submit returns a "coming soon" 400. Run `veri gpu list` to see which providers are live.
</Note>

## Choosing a provider

Pass `provider` when creating a training job:

```python
from veri_sdk import Client
client = Client()

job = client.training_jobs.create(
    base_model="Qwen/Qwen2.5-0.5B-Instruct",
    dataset_id=dataset.id,
    reward_source=open("reward.py").read(),
    output_name="qwen-0.5b-do",
    method="grpo",
    gpu_type="H100-80GB",
    gpu_count=1,
    provider="digitalocean",
    hyperparameters={
        "learning_rate": 1e-6,
        "max_steps": 50,
    },
)
```

From the CLI:

```bash
veri train --provider digitalocean --gpu-type H100-80GB --gpu-count 1
```

Or in a TOML config:

```toml
kind = "train"
provider = "digitalocean"
gpu_type = "H100-80GB"
gpu_count = 1
```

Omit `provider` to use the default (AWS).

## Checking live availability

Capacity is per-provider and per-region. Check what's available right now before submitting:

```bash
veri gpu list                    # all providers, all regions
veri gpu list --provider vast     # Vast.ai only
veri gpu list --provider digitalocean  # DigitalOcean only
veri gpu list --gpu-type H100-80GB  # filter by GPU type
```

The `available` column shows live capacity: a real-time count of GPUs that can be launched immediately. `0` means the shape is offered but currently out of stock — retry later.

## Pricing

Each provider has its own rate card. Check current pricing with:

```bash
veri gpu list --format json   # includes usd_per_hour per GPU type
```

Rates are per-GPU-hour. You are billed from the moment the instance boots (during `provisioning`, before the first training step) until the job terminates and the instance is reaped. This applies to failed jobs too: GPU time actually used is billed. A job that never secures a GPU (e.g. `CAPACITY_UNAVAILABLE`) rents nothing and is not billed.
