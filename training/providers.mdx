Veri runs training jobs on four GPU providers. You pick one at job submit time with the `provider` field. Each provider offers different GPU types at different price points: AWS is the default, Vast.ai is the NVIDIA marketplace spillover, DigitalOcean offers 1x and 8x H100 droplets with per-second billing, and GCP offers a single A100 80GB or H100 80GB on Flex-start VMs.

## Providers at a glance

| Provider | GPUs offered | Architecture | Billing | Status |
| --- | --- | --- | --- | --- |
| [`aws`](/training/providers/aws) (default) | L4, A10G, A100 80GB, H100 80GB | NVIDIA (Ampere/Hopper) | Per-second, on-demand | Available |
| [`vast`](/training/providers/vast) | A100 80GB, H100 80GB (1, 2, 4 or 8 GPUs) | NVIDIA (marketplace) | Per-second, marketplace pricing | Available |
| [`digitalocean`](/training/providers/digitalocean) | H100 80GB (1 or 8 GPUs) | NVIDIA (Hopper) | Per-second, on-demand | Available |
| [`gcp`](/training/providers/gcp) | A100 80GB, H100 80GB (1 GPU) | NVIDIA (Ampere/Hopper) | Per-second, Flex-start (from when the VM has its GPU) | Available |

GCP training runs on Flex-start VMs: a GCP job can wait in `queued` for up to about 15 minutes while Veri looks for capacity, and Veri runs one GCP GPU at a time for now. If GCP ends the VM early the job fails with `provider_reclaimed` (credited back) or, at the 24-hour limit, `max_run_duration_reached`; resume it from a checkpoint. See [GCP](/training/providers/gcp).

<Note>
  All providers except AWS are gated behind feature flags. If a provider is disabled, submit returns a 400 saying the provider isn't available yet. Run `veri gpu list` to see which provider and GPU combinations are offered for training.
</Note>

## Choosing a provider

Pass `provider` when creating a training job:

```python
from veri_sdk import Client
client = Client()

job = client.training_jobs.create(
    base_model="Qwen/Qwen2.5-0.5B-Instruct",
    dataset_id=dataset.id,
    reward_source=open("reward.py").read(),
    output_name="qwen-0.5b-do",
    method="grpo",
    gpu_type="H100-80GB",
    gpu_count=1,
    provider="digitalocean",
    hyperparameters={
        "learning_rate": 1e-6,
        "max_steps": 50,
    },
)
```

From the CLI, override the provider and GPU of a [config file](/cli/training):

```bash
veri jobs create configs/train.toml --set provider.name=digitalocean --gpu-type H100-80GB --gpu-count 1
```

(`veri train my_job.py --provider digitalocean` does the same for a script with a `@training_job` decorator, which sets the GPU itself.)

Or in a TOML config:

```toml
kind = "train"

[provider]
name = "digitalocean"

[resources]
gpu_type = "H100-80GB"
gpu_count = 1
```

Omit `provider` to use the default (AWS).

## Checking live availability

Capacity is per-provider and per-region. Check what's available right now before submitting:

```bash
veri gpu list                          # catalog: every provider and GPU, node sizes, price per GPU-hour
veri gpu list --provider vast          # live availability on Vast.ai, per region
veri gpu list --provider digitalocean  # live availability on DigitalOcean, per region
veri gpu list --gpu-type H100-80GB     # live availability for one GPU type
```

Bare `veri gpu list` is the static catalog: which node sizes each provider sells for training and serving, and the price per GPU-hour. Add any filter (`--provider`, `--gpu-type`, `--region`) for the live view: one row per provider, GPU type and region with a `status` (`AVAILABLE` for a DigitalOcean region or Vast offer, `OFFERED` for an AWS catalog entry, `UNAVAILABLE` when there is no capacity) and a `signal` column (`qty N` for a live DigitalOcean or Vast count, `spot N/10` for the AWS Spot placement score). AWS `OFFERED` is not a launch guarantee.

## Pricing

Each provider has its own rate card. Check current pricing with:

```bash
veri gpu list --format json   # includes usd_per_gpu_hr per provider and GPU type
```

Rates are per-GPU-hour. You are billed from the moment the instance boots (during `provisioning`, before the first training step) until the job terminates and the instance is reaped. This applies to failed jobs too: GPU time actually used is billed. A job that never secures a GPU (e.g. `CAPACITY_UNAVAILABLE`) rents nothing and is not billed. The checkpoints a job keeps are billed separately, per GiB-month kept; see [Checkpoint storage](/billing#checkpoint-storage).
